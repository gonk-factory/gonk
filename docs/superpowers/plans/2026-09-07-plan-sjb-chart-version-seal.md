# Plan v2: stop every commit redeploying gonk, without letting a chart change silently not deploy

**Bead:** gonk-sjb (P1, claimed) · **Date:** 2026-09-07
**Owner decisions:** patch bump on every chart-content change; mirror (gonk-v1u) waits on
gonk-8g9 / gonk-dku / gonk-jn5.
**Status:** v2, after adversarial review. v1's gate did not close the failure it existed to
close; three defects and one better design came out of that review and are folded in below.

## 1. The problem, measured

`clusters/orac/apps/gonk/helmrelease-gonk.yaml` sets `reconcileStrategy: Revision`. Flux
stamps the source git revision into the chart version, so the rendered version is
`0.1.0+<sha12>` and **every** commit to gonk main is a new chart version and therefore a
Helm upgrade that rolls controller, intake, meter and dolt.

| release | chart version | trigger |
|---|---|---|
| 886 | `0.1.0+504b4f984b0b` | a real chart change |
| 887 | `0.1.0+7f479416c20c` | a **bead-only** commit |

The counter stands at 888. gonk commits its own beads to its own repo, those commits
redeploy gonk, and the redeploy restarts intake mid-flight so a webhook arriving in that
window is dropped -- two of four triage smoke tests on 2026-09-07 (issues 65, 67).

**Scope honesty (review NB7):** `ChartVersion` cuts the *frequency* of rolls. It does not
make intake survive one. A real chart change or a gitops image-tag bump still rolls it, and
the controller is `strategy=Recreate` by design. Intake webhook durability is a **separate
bead** (item 12); gonk-sjb must not be read as curing the dropped-webhook class.

## 2. The trap in the obvious fix, and why v1's gate did not close it

`reconcileStrategy: ChartVersion` makes Flux upgrade only when `Chart.yaml`'s `version:`
changes. Verified in the CRD and in upstream source (see 3.6). That introduces:

> Edit chart content, do not bump the version, commit. CI is green, nothing complains --
> and Flux never deploys it. The cluster silently runs the old chart.

v1 proposed a seal recording `version + sha256(tree)` and a test that both agree. **That is
insufficient**, and the reason is the whole reason for v2:

source-controller v1.8.5 `internal/helm/chart/builder_local.go` reuses the cached chart when
`result.Name == curMeta.Name && result.Version == curMeta.Version`, and
`helmchart_controller.go:764` sets `Force: obj.Generation != obj.Status.ObservedGeneration`
-- the *HelmChart object's* generation, which a new git commit does not change. So reuse is
decided on **name+version only**. Therefore all of these pass a self-consistency seal and
still never deploy:

- two branches that both bump `0.1.0 -> 0.1.1`;
- a `git revert` that restores content but not the version;
- an amend reusing a version already packaged.

**The seal must assert the version is NEW, not merely consistent.** Hence the ledger (3.1).

## 3. Design

### 3.1 The seal is an append-only ledger

`chart/CHART-SEAL`, outside the chart directory:

```
# Append-only. Generated by `make chart-seal`. Never edit or reorder by hand.
# <semver> <sha256 of chart/gonk>
0.1.0 3f2a...c1
0.1.1 9b40...7e
```

Outside `chart/gonk/` deliberately: there is no `.helmignore` anywhere in this repo
(verified), so a file inside the chart directory *is* packaged and would need a
self-exclusion, and an exclusion rule is one more thing that can be wrong.

Append-only buys three things a single-line rewrite does not:

1. **Strict monotonicity is checkable.** The newest entry must be semver-greater than every
   prior entry, which is what makes a revert-to-an-old-version fail.
2. **No version is ever reused.** A duplicate is a test failure, closing the collision case.
3. **Two branches conflict in git.** Both append to the same last line, so the collision
   surfaces as a merge conflict rather than as a silent no-deploy. A rewrite-in-place would
   let `make chart-seal` "resolve" it and carry the collision through.

Hash: deterministic walk of `chart/gonk`, paths sorted, each file contributing
`relpath\0len(content)\0content`. Skip nothing, so a future `chart/gonk/.helmignore` is
covered by construction. Symlinks are not followed and their *target string* is hashed;
file mode is not hashed (helm does not preserve it); empty directories contribute nothing.

**`chart/values-e2e.yaml` is deliberately NOT sealed** (review NB3). It is an e2e fixture,
never packaged and never deployed, so forcing a chart version bump for editing it would be
friction with no safety benefit -- and friction is what gets routed around.

### 3.2 The gate

`internal/buildgate/chart_seal_test.go`, in the **ordinary** `go test ./...` gate -- not
behind `-tags chart`, and needing neither helm nor a cluster. This matters more than v1
realised: `chart-test` is gated on `rules: - if: $GONK_CHART_TOOLS_IMAGE`, and that variable
is **defined nowhere in the repo**, so the golden gate does not run in CI at all. The seal
test would be the only chart guard executing on every commit.

Assertions:

1. `chart/CHART-SEAL` exists, parses, and is non-empty.
2. Every line is a valid `<semver> <64-hex>` pair.
3. No version appears twice.
4. The last entry's version is strictly semver-greater than every prior entry.
5. The last entry's version equals `chart/gonk/Chart.yaml`'s `version:`.
6. The last entry's sha256 equals the recomputed hash of `chart/gonk`.

The failure message names the remedy: bump `version:` in `chart/gonk/Chart.yaml`, then run
`make chart-seal`.

### 3.3 What the gate actually guarantees (review B4 -- v1 overclaimed)

v1 said the gate makes the mistake "impossible to commit". **False.** gonk commits go direct
to main, so the gate is post-hoc detection: by the time CI is red, the un-bumped edit is on
main and Flux has already declined to deploy it. This repo's own history is that pipeline
state gets trusted without being read.

The honest claim is: **a commit that skips the bump cannot pass CI.** To get closer to
prevention, `make gate` (which already runs `go test ./...`) goes into the session-close
protocol before push. That is a discipline, not a mechanism, and is recorded as such.

### 3.4 Version-normalized goldens (review F(iv)) -- the change that makes this workable

v1 claimed a version bump's golden diff would be "only the `helm.sh/chart` label". Measured:
a pure `0.1.0 -> 0.1.1` bump changes **478 lines across the eight goldens**
(64/28/80/78/64/56/42/66), because `_helpers.tpl:15` emits `helm.sh/chart` on every object
(231 occurrences) **and** the `checksum/operator-config` pod annotation hashes a ConfigMap
that itself carries that label.

Burying every real chart review under ~470 lines of label churn, in a gate that only runs
when someone remembers to run it locally, is a workflow that gets skipped.

So: `charttest` renders from a **copy** of `chart/gonk` in `t.TempDir()` with `Chart.yaml`'s
`version:` rewritten to the sentinel `0.0.0-golden`. A version bump then changes **zero**
golden lines -- including the checksum annotation, which naive string substitution would not
fix. Consequences:

- work item 7 (regenerate goldens on every bump) disappears entirely;
- `make chart-seal` becomes pure Go with no helm dependency, killing the half-updated-tree
  hazard in 3.5;
- the golden diff stays reviewable, which is the gate's entire stated purpose.

The goldens stop asserting the real chart version. That is fine: the seal asserts it, and
asserts it against content, which the goldens never did.

### 3.5 Two make targets, never one

v1 folded a pure-Go step and a helm step into one target. If the helm half failed,
`CHART-SEAL` was already written and the resulting tree **passed the seal gate with stale
goldens**. Neither helm nor kubeconform exists in CI's `golang:1.26` image, and the
Makefile's own `lint` target exists because a tool was missing on a dev box.

- `make chart-seal` -- pure Go, appends to the ledger. No helm.
- `make chart-goldens` -- the existing `-tags chart ... -run Golden -update`. Needs helm.

With 3.4 in place these are independent: a version bump needs only the first.

### 3.6 Flux behaviour, verified rather than assumed

- `kubectl explain helmrelease.spec.chart.spec` returns verbatim: *"version — Version semver
  expression, ignored for charts from v1.GitRepository and v1beta2.Bucket sources."* So the
  `'*'` is inert. **Correction to v1 §5:** the field is not in the gitops file at all; the
  `'*'` is the CRD default and appears only on the live object.
- `helmchart_controller.go:772-795` sets `opts.VersionMetadata` from the git sha **only**
  when `ReconcileStrategy == Revision`. Deployed: source-controller v1.8.5, helm-controller
  v1.5.5.

### 3.7 Rejected alternatives, with citations

- **GitRepository `spec.ignore`, keeping `Revision` (the bead's option 2): DEAD.**
  `gitrepository_controller.go:819` builds the artifact with `commitReference(obj, commit)`
  as its revision; `Ignore` is applied only at `storage.Archive` time (877-889) as a file
  filter. The revision is the commit sha regardless of what is filtered, so every commit
  still yields `0.1.0+<sha12>` and a full roll. Record this in the bead so nobody retries it.
- **Move `.beads/` out of the repo: partial.** 74 of the last 200 commits (37%) touch only
  `.beads/`; docs, plans and chart edits produce the rest. Also fights CLAUDE.md's "use bd
  for ALL task tracking". Worth doing on its own merits, not as this fix.
- **Flux `Kustomization` path filter: does not apply.** The chart is not delivered by a
  Kustomization -- `HelmChart/flux-system/gonk-gonk` consumes `GitRepository/gonk` directly.
- **Auto-derive the version from the hash: rejected on merit, not mechanism.** Since
  `version` is inert for git sources there is no range-resolution problem, but it makes every
  version a meaningless hash in `helm history` and in the `helm.sh/chart` label, and removes
  the deliberate release boundary the owner asked for.

## 4. Work items

0. **`driftDetection`, same commit as the strategy flip.** Under `Revision` the chart was
   re-applied on essentially every commit, so a hand `kubectl edit` was corrected within
   minutes as a side effect. `spec.driftDetection` is absent from the whole `clusters/` tree
   and defaults to disabled, so after the flip a manual edit persists indefinitely. Add
   `spec.driftDetection: {mode: enabled}` to restore the property that is being removed.
1. **gitops:** `reconcileStrategy: Revision` -> `ChartVersion`. Direct to main, no MR.
2. **Chart version:** `chart/gonk/Chart.yaml` `0.1.0` -> `0.1.1`. `appVersion` is the gonk
   release and is NOT bumped here.
3. **Traceability, and its loss documented.** Every object today carries
   `helm.sh/chart: gonk-0.1.0_<sha12>` -- a live link from a running pod to a commit. After
   the flip the label is `gonk-0.1.1` forever. Worse, source-controller's cache is an
   `emptyDir`, so a restart repackages HEAD under the unchanged version and `0.1.1` can name
   two different trees. Mitigations, all required:
   - the ledger maps version -> content hash;
   - `git log -S'<version> ' -- chart/CHART-SEAL` maps a ledger line to the commit that
     added it;
   - the HelmRelease comment block gains the new procedure and an explicit statement that
     the label no longer carries a sha.
   Residual risk, stated not hidden: a direct-to-main push whose red pipeline nobody read.
4. **Seal hasher + ledger writer**, shared by the gate and the make target so they cannot
   drift; follows the repo's existing `-update` convention rather than adding a binary.
5. **Gate:** `internal/buildgate/chart_seal_test.go`, assertions 1-6 of 3.2, written as pure
   functions over inputs so negative controls can drive them.
6. **Negative controls** for each of the six assertions, including the two v1 lacked:
   duplicate version, and non-monotonic version.
7. **Version-normalized goldens** per 3.4, plus one regeneration to the sentinel.
8. **Makefile:** `chart-seal` and `chart-goldens` per 3.5; `make gate` into session-close.
9. **`.gitattributes`:** `chart/** -text`. The hash reads working-tree bytes; `core.autocrlf`
   and `core.eol` are unset and no `.gitattributes` exists, but the repo lives on `/mnt/c/`
   and one Windows checkout or a future `text=auto` would break the gate for everyone.
10. **Mutation test against the REAL tree:** chart edit without bump -> fail; bump without
    reseal -> fail; reseal without bump -> fail; duplicate version -> fail; lower version ->
    fail; bump + reseal -> pass. Restore byte-identical and prove it.
11. **Live verification, the actual claim.** Expect **two** upgrades, not one: flipping
    `reconcileStrategy` changes the HelmChart spec -> generation bump -> `Force: true` ->
    revision goes `0.1.0+<sha>` -> `0.1.0`, which helm-controller reads as a version change
    (release 889); the `0.1.1` bump is the second (890). Then push a **bead-only** commit and
    confirm the counter stays at 890. `status.history`, not a green test.
12. **File a separate bead** for intake webhook durability (PDB, RollingUpdate, graceful
    drain, or intake-side retry), per 1's scope-honesty note.
13. **Bead:** gonk-sjb notes record the fix, the hazard it creates, the gate that closes it,
    and 3.7's dead options. Close only after item 11.
