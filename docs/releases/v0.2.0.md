# gonk v0.2.0

The second release: failed pipelines are diagnosed, a diagnosis can be followed
by a fix merge request that gonk then judges on its own pipeline, and every
agent session now runs as a Kubernetes Job that gonk creates itself.

This file is the release notes of v0.2.0. Its first paragraph is the body of
the release commit. `CHANGELOG.md` has the same content in changelog form.

## What this release is

gonk is a self-hosted software factory for GitLab: webhooks in, triaged issues
and reviewable changes out, with every model call metered against a
per-project budget. v0.2.0 is also the **first commit of this repository's
public history**: the repository is a release mirror (see `CONTRIBUTING.md`),
and each release from here on is one snapshot commit.

## Status of each workflow

Stated per workflow, because "it is in the tree" and "it does something" are
different claims. A project opts in to each one in its `.gonk.yml`; a project
that has not opted in sees nothing.

| Workflow | Opt-in | Status in v0.2.0 |
|---|---|---|
| Issue triage | `actions.triage` | **Active.** As in v0.1.0, on the new session runtime. |
| Pipeline-failure diagnosis | `actions.pipelines` | **Active. New.** A failed pipeline gets one tracking issue with a diagnosis grounded in the job logs. |
| Pipeline-fix merge requests | `actions.pipeline_fixes` (needs `pipelines`) | **Active. New. gonk merges nothing.** After a diagnosis gonk may open one fix merge request, reads that merge request's pipeline (the exit check), reports what it found, and tries again within `max_attempts`. A person merges. |
| Issue to merge request | `actions.features`, `change:` | **Not active.** The configuration is validated, folded and reported; nothing dispatches it and no agent exists for it. A triage verdict of "code change" on such a project writes a label and stops. |
| Independent review | `actions.reviews`, `review:` | **Not active.** Configuration only; no review agent exists and gonk writes no review. |
| Merge policy | `pipeline_fix.auto_merge`, `change.auto_merge` | **Not active.** The keys are read and not acted on. gonk does not merge under any setting. |

`docs/reference/gonk-pipeline-fix.md`, `gonk-change.md` and `gonk-review.md`
each open with the same status, and say exactly what is and is not built.

## Added

- **Pipeline-failure diagnosis.** One record and one tracking issue per failing
  run of a target (a merge request or a ref), keyed on the set of failing jobs
  and the last green pipeline. The agent is read-only; the controller checks
  every quoted log line against an excerpt it re-derives, checks that every
  cited file exists at the diagnosed commit, and writes the note itself.
- **Pipeline-fix merge requests, with the exit check.** A read-only session
  proposes edits; the controller gates them (scope, path classes, per-kind
  caps, a fixed list of refusals for edits that only silence a failure),
  commits them to a `gonk/pipefix-*` branch and opens one merge request linked
  to the diagnosis. It then reads the merge request's own pipeline at most
  every two minutes until `verify_timeout`, says what it found on the merge
  request, on the diagnosis and to the meter, and after a person merges it
  checks the target's next pipeline.
- **The Kubernetes Jobs session runtime** (ADR-008). gonk-gate creates one
  `Job` per session from the agent image, with the prompt, the checkout and the
  per-project key mounted as a Secret; the reservation's lifetime is the Job's
  deadline, and a session is never silently retried. It replaces sessions run
  through the embedded orchestrator's own pod provider.
- **Workflow scope: path classes, layers and ecosystem profiles.** Every path a
  change may touch has exactly one class (`control`, `secret`, `ci`, `deploy`,
  `deps`, `test`, `docs`, `source`, ...), decided without a model. Pack,
  operator and project configuration fold into one policy; shipped profiles
  supply the test, docs, source and dependency patterns per ecosystem. The
  pipeline-fix gates are its first consumer. See `docs/reference/gonk-scope.md`.
- **Retry feedback.** An answer a static gate refuses is no longer retried with
  a byte-identical prompt: the next attempt is told, in one controller-built
  sentence, what was wrong and what the allowed set is. No model text is
  replayed. Wired for pipeline diagnosis and pipeline fixes.
- **One release tag for every image, and a floor per image.** The chart takes a
  single `releaseTag`; `Chart.yaml` records the oldest build of each image the
  chart may be rendered against, and the render refuses anything older.
- **Trust for a private CA is additive.** With a CA ConfigMap named, the chart
  adds its directory to the system roots instead of replacing them.

## Changed

- The meter contract and the `.gonk.yml` and operator schemas gained keys for
  the workflows above. Every addition is optional: a configuration file that
  does not mention them resolves exactly as before.
- The state record gained the pipeline run identity, the failure facts and the
  retry feedback (`docs/reference/gonk-state-record.md`). All additive.
- A `fix_meta` effect's explanation key is `reason`; `rationale` is refused
  like any unknown field (`docs/reference/effects-contract.md`).

## Upgrading from v0.1.0 (breaking)

Read `chart/gonk/README.md`, "Upgrading from the v0.1.0 release", before a `helm upgrade`.
In short:

1. **Go module path.** The module is `github.com/gonk-factory/gonk`. Anything
   that imported the old path must change its imports.
2. **Chart defaults that are now required or empty.** Seven values no longer
   default to the maintainers' own. `gitlab.url` is required (the render fails
   without it). `image.registry` defaults to the public registry and
   `image.pullSecrets` to none. `gitlab.caCert.existingConfigMap`,
   `gitlab.caCert.key`, `ingress.host` and `ingress.annotations` default to
   empty: a private CA that is no longer named is simply not mounted. Set what
   you relied on **before** upgrading. Other defaults still describe the
   maintainers' environment (see "Known issues").
3. **Label and annotation key domain, and the drain.** Every key gonk owns is
   now under `gonk-factory.github.io/`. gonk-gate finds a session's Job, pod
   and Secret by label, so a session started before the upgrade is invisible
   after it -- never reaped, never resolved, and nothing errors. Drain first:
   wait until no session Job exists under the old key, upgrade, then look
   again and delete any straggler by hand. The chart README has the commands.
4. **Trust variables.** No image sets `SSL_CERT_FILE`, and neither does the
   chart. With a CA configured the chart sets
   `SSL_CERT_DIR=/etc/ssl/certs:<the directory of gitlab.caCert.mountPath>`;
   the default mount path is `/etc/ssl/gonk/ca.crt`. Session pods are given no
   private CA.
5. **Schema `$id`s.** The configuration schemas are identified by
   `https://raw.githubusercontent.com/gonk-factory/gonk/main/docs/schemas/<file>`.
   An editor or validator that pinned the old `$id` must be repointed. The
   header gonk writes into an onboarding merge request names the new one;
   files onboarded earlier keep their old comment line, which is harmless.
6. **Plain release tags and the image floor.** The images of this release are
   tagged `v0.2.0`, which carries no build number, so the chart's floor check
   cannot rank it and refuses it by default. Installing from the published
   images needs `imageFloor.acceptUnrankedTags=true` together with
   `releaseTag: v0.2.0`. The chart has its own version: the packaged chart
   attached to this release is `gonk-0.2.1.tgz`. `chart/gonk/README.md`,
   section 2, has the minimal values for an install.
7. **Intake and the controller must come from one build.** Their wire contract
   changed together; do not mix images of this release with v0.1.0's.

## Known issues

- **A model-gateway outage takes readiness down.** While the LiteLLM proxy is
  unreachable gonk-meter reports not ready, gonk-intake then cannot register
  projects and is not ready either, and a `helm upgrade` in flight fails. No
  alert ships for it. (`gonk-88ez`)
- **Retry feedback is not wired for issue triage.** A triage answer refused by
  a gate is still retried with the same prompt. (`gonk-hpgy`)
- **A diagnosis effect may carry a fix kind's keys.** `old`, `new`, `paths` and
  `reason` on a diagnosis effect are accepted and ignored: nothing is read or
  written from them. It is a looseness in a gate, not a way through one.
  (`gonk-8yux`)
- **Two tests can fail on a loaded machine.** In `internal/testnet` and
  `test/harness`, a test that asks the kernel for a free port treats a
  host-wide shortage of ephemeral ports as its own failure. Seen only with
  several test runs sharing one host. (`gonk-njmr`)
- **NetworkPolicies are enforced only where the cluster's CNI enforces them.**
  `helm test <release> -n <namespace>` reports ENFORCED or NOT ENFORCED for
  your cluster.
- **Not proven on a real project.** The pipeline-fix workflow has been
  exercised against a synthetic project only.
- **Some chart defaults still describe the maintainers' environment, and you
  must override them.** `intake.blockedProjects` defaults to a project path on
  the maintainers' GitLab, which blocks nothing on yours.
  `ledger.postgres.mode` defaults to `shared`, with
  `ledger.postgres.shared.clusterName` and `.clusterNamespace` naming their
  Postgres cluster, and `networkPolicy.ledgerPostgres.namespaceSelector`
  defaults to that cluster's namespace, so in modes `shared` and `external`,
  on a cluster that enforces NetworkPolicy, the meter cannot reach a ledger
  anywhere else until you set it. `ingress.className` and
  `networkPolicy.ingressController.namespaceSelector` default to their
  ingress controller. The other selectors under `networkPolicy` assume
  namespaces named `gitlab`, `litellm` and `monitoring`. The table in
  `chart/gonk/README.md`, section 2, lists each one. The defaults will be
  emptied or made required in a later release. (`gonk-mp43`)

The identifiers in parentheses are from the maintainers' issue tracker, which
is not public; they are given so a later release can say which one it closed.

## Supply chain

Every image is signed and carries two attestations, verifiable without
trusting this text:

    gh attestation verify oci://ghcr.io/gonk-factory/gonk/gonk-intake:v0.2.0 --owner gonk-factory
    cosign verify ghcr.io/gonk-factory/gonk/gonk-intake:v0.2.0 \
      --certificate-identity-regexp '^https://github.com/gonk-factory/gonk/' \
      --certificate-oidc-issuer https://token.actions.githubusercontent.com

SLSA build provenance and an SPDX SBOM are attached to each image digest. The
images are built by this repository's release workflow from the release commit.
The four images are `gonk-agent`, `gonk-controller`, `gonk-intake` and
`gonk-meter`.
