# gonk v0.2.1

A maintenance release: the defects known when v0.2.0 shipped and the findings
of its review are fixed or stated. No workflow is added. The chart now lets
gonk work on a cluster that enforces NetworkPolicy, the pipeline-fix workflow
is hardened against text it does not control, and refused answers from the
triage and scaffold agents are retried with feedback.

This file is the release notes of v0.2.1. Its first paragraph is the body of
the release commit. `CHANGELOG.md` has the same content in changelog form.

## What this release is

The same three active workflows as v0.2.0 (issue triage, pipeline-failure
diagnosis, pipeline-fix merge requests), with the same opt-ins; the status
table in `docs/releases/v0.2.0.md` still holds, and the three workflows that
were not active are still not active. The chart version is **0.2.4**; the
images are tagged `v0.2.1`.

Read "Upgrading from v0.2.0" before a `helm upgrade`: one value is new and
must be set on a cluster that enforces NetworkPolicy, one default changed,
and three behaviours are stricter.

## Fixed

### NetworkPolicy, on a cluster that enforces it

In v0.2.0 the chart's policies, where they were enforced, stopped gonk from
working. Three rules were wrong or missing:

- **Agent sessions and the controller can reach gonk-intake's private
  listener.** Both had the egress rule; intake's ingress admitted neither, so
  a session had no checkout. Intake now admits them on that port. This also
  opens something that was closed by accident: see "Known issues", first
  entry.
- **The controller's DNS rule allows TCP as well as UDP.**
- **Egress to the Kubernetes API server**, which the controller needs to
  create a session Job and the meter needs to write a project's key Secret,
  is rendered from a new value, `networkPolicy.kubeAPI.cidrs`. It is empty by
  default and an empty value renders no rule: **you must set it** on an
  enforcing cluster ("Upgrading", item 1). A prefix shorter than `/8` (IPv4)
  or `/16` (IPv6) is refused, and so is a rule with no port.

Seen working on k3s with kube-router. The description of the meter's Role in
`values.yaml` was also wrong (it claimed the grant was scoped to the key
Secrets) and now says what renders; the grant is unchanged ("Known issues").

### Pipeline-fix hardening

Text that a project, a model or a redirecting server controls can no longer
do these things:

- **A fix merge request's title or commit message cannot carry a closing
  pattern.** A failed job named `fixes #12` used to reach both. The title is
  rewritten where it would read as a closing statement, and title and message
  are checked before anything is written.
- **Model text in a diagnosis note is quoted.** The summary and the remedy
  are rendered as a code block, so a mention, an issue reference or a link in
  them is inert.
- **A quick action after a carriage return is refused.** A diagnosis whose
  text held `\r/close` was applied in v0.2.0.
- **A batch is exactly one JSON object.** Text after the object (prose, a
  second object) refuses the batch; so does a key of the batch stated twice,
  where the decoder used to take the last one silently.
- **The GitLab token is not sent to another origin on a redirect.** A read
  that is redirected elsewhere is followed without the token; a write is not
  followed.
- **Nested CI includes are followed.** A file included by an included file is
  pipeline definition (class `ci`) and is covered by the check that a fix did
  not change the definition. Where the set of included files cannot be known
  from the files alone (a wildcard, a variable in the path, a `!reference`),
  the merged definitions are compared instead.
- **A merged-results or merge-train pipeline is never used as evidence** that
  a fix worked. It runs on a commit gonk did not make, and nothing in
  GitLab's API ties it to the fix commit ("Known issues").
- **A diagnosis effect that carries another kind's keys** (`old`, `new`,
  `paths`, `reason`) is refused instead of accepted with the keys ignored.

### Retry feedback

- **Issue triage and scaffolding are wired.** A triage or scaffold answer
  that a gate refuses is retried with a controller-built sentence saying what
  was wrong, as diagnosis and fix answers already were.
- **A refused diagnosis is told its closed sets**: the names of the failed
  jobs and the fact keys an evidence item may use. A job name is shown only
  when it is a single token of letters, digits and `-_.:/`; any other name
  is counted, and the model is pointed at the job headings.

### Gate checks that could be evaded

- A test function that opens with `if testing.Short() { return }` (or any
  guarded leading return) counts as a skipped test.
- A CI line that ignores a failure with `|| :` or `|| true` is recognised
  when a `;` or a comment follows it, not only at the end of the line.

### Tests and the build

- Two tests that failed on a busy machine when the host ran short of free
  ports are fixed in the tests.
- The lint step keeps a cache per checkout, so a deleted checkout's stale
  entries no longer turn it red.
- **Downloads in the workflows are pinned**: cosign, k3d and kind by
  checksum, Calico's manifest by commit and checksum, the Postgres service
  image by digest. A test refuses an unpinned download.
- The test behind the chart README's statement about TLS verification now
  checks what the statement says, and the statement says exactly what the
  test checks (`chart/gonk/README.md`, section 5).

### The public tree

Eleven files that a user of gonk cannot use are no longer published: records
of the maintainers' own test runs, tooling that only works against their
infrastructure, and their internal pipeline definition. The public CI is
`.github/workflows/`. Comments and documents that described the maintainers'
environment as fact now state conditions, ADR-008 is marked accepted, and the
install notes list every Secret the chart needs.

## Changed

- `change.triggers` defaults to `[label]` (it was `[label, command,
  mention]`). The issue-to-merge-request workflow is not active, so nothing
  starts differently; the resolved configuration that the meter reports
  changes for a project that sets no triggers.
- `intake.blockedProjects` defaults to `[gonk-factory/gonk]`, the upstream
  project's path, in place of a path on the maintainers' GitLab.
- Chart 0.2.4. See "Upgrading" for what changes in the rendered objects.

## Upgrading from v0.2.0

Nothing here applies to a first install except items 1 and 2.

1. **Set `networkPolicy.kubeAPI.cidrs` if your cluster enforces
   NetworkPolicy.** Without it the default-deny policy cuts the controller
   and the meter off from the Kubernetes API server: no session Job is
   created and no project key is delivered. Give the addresses behind the
   `kubernetes` Service -- its EndpointSlice -- and their port, not the
   Service's cluster IP (policy is evaluated after the Service address is
   translated, so the cluster IP matches nothing):

       kubectl --context <context> -n default get endpointslices \
         -l kubernetes.io/service-name=kubernetes \
         -o jsonpath='{range .items[*]}{.endpoints[*].addresses[*]}{" port "}{.ports[*].port}{"\n"}{end}'

       networkPolicy:
         kubeAPI:
           cidrs: ["192.0.2.10/32"]
           ports: [6443]

   Some network plugins do not match an `ipBlock` against a node's address
   (Cilium does not unless it is configured to). There the API server has to
   be allowed by a policy of that plugin's own kind, beside this chart.
   `helm test <release> -n <namespace>` says whether your cluster enforces.
   On a cluster that does not, the value changes nothing. A value of `/0`,
   or any prefix shorter than `/8` (IPv4) or `/16` (IPv6), fails the render.
2. **`intake.blockedProjects` no longer names the maintainers' project.** The
   default is `[gonk-factory/gonk]`. If you host gonk's own source on your
   GitLab and relied on the old default to keep gonk from working on it, list
   that project's path yourself.
3. **Pods roll.** The chart-version label (`helm.sh/chart`) and the application
   version label are on every pod template, so gonk-intake, gonk-meter, the
   controller and the Dolt StatefulSet all restart on this upgrade, as they
   do on any change of chart version. Rendered with the same values, the
   chart of v0.2.0 (0.2.1) and this one (0.2.4) differ, besides those labels,
   in: the `gonk-intake` and `gonk-controller` NetworkPolicies (the rules
   under "Fixed"); the wording of the enforcement annotation on every
   NetworkPolicy; gonk-intake's `GONK_VERSION` and `GONK_BLOCKED_PROJECTS`;
   and the meter's `checksum/operator-config` annotation. No Role, Service or
   workload spec changes otherwise. `chart/gonk/README.md`, section 6, lists
   the changes per chart version.
4. **`change.triggers` defaults to label only.** A project that opted in to
   `actions.features` and wrote no `triggers` now resolves to `[label]`.
   Nothing dispatches on these triggers in this release.
5. **Use the `https://` URL of your GitLab.** If `gitlab.url` is an `http://`
   address that GitLab redirects to `https://`, the redirect is a change of
   origin and the token is no longer sent across it: reads come back
   unauthenticated and writes are not followed. Set `gitlab.url` to the
   address GitLab actually serves.
6. **Stricter parsing of an agent's answer.** A diagnosis that carries a fix
   kind's keys, an answer with any text after its JSON object, and an answer
   that states `effects` or `verdict` twice are refused and retried with
   feedback. In v0.2.0 the first was accepted with the keys ignored, and the
   other two were read as their first object and their last key.
7. **Diagnosis notes look different.** The summary and the remedy are shown
   as a code block: text in them does not wrap in GitLab's view, and
   mentions and references in them are no longer live.
8. **Some projects that got a fix merge request no longer do.** A project
   whose CI definition has a nested include that gonk's YAML parser rejects,
   or a local include of the form `configs/**.yml` (`**` inside a path
   segment, which GitLab accepts and gonk's pattern syntax does not), gets a
   diagnosis and no fix.

Intake and the controller must still come from one build, and the images of
this release are tagged plainly `v0.2.1`: installing them needs
`imageFloor.acceptUnrankedTags=true` with `releaseTag: v0.2.1`, as in
v0.2.0. The packaged chart attached to this release is `gonk-0.2.4.tgz`.

## Known issues

- **gonk-intake's private listener is not authenticated, and session pods can
  now reach it.** The routes that register a checkout and that trigger a
  reconcile take no credential. On a cluster that enforces NetworkPolicy,
  v0.2.0 blocked agent session pods from that listener (by mistake: it is
  also why sessions there had no checkout); v0.2.1 admits them, so a session
  can register and fetch any project the forge token can read. Where
  NetworkPolicy is not enforced this was already so. It matters where one
  install serves projects with different trust boundaries; it is not a
  concern for a single-tenant install. (`gonk-37kg.3`)
- **A CloudNativePG ledger has no NetworkPolicy of its own.** With
  `ledger.postgres.mode: cnpg` the Postgres pods are in the release
  namespace, the default-deny policy selects them, and no rendered policy
  admits a client to them. Use `shared` or `external`, or add a policy for
  those pods. Read from the rendered policies; not tried on a cluster.
  (`gonk-37kg.4`)
- **The NetworkPolicy fixes were observed on one network plugin.** k3s with
  kube-router. Calico and Cilium are untested, and Cilium needs its own
  handling for the API-server rule ("Upgrading", item 1).
- **A fix cannot be verified on a project that uses merged-results pipelines
  or merge trains.** Such a pipeline is never taken as evidence, so the fix
  merge request is opened and its outcome is reported as "unverifiable".
  (`gonk-ow8u`)
- **Diagnosis answers are often refused for their format.** With the
  reference model, a sizeable share of first diagnosis attempts are refused
  by the format gates. The retry is told what was wrong and does not always
  recover; the pipeline then gets a "denied" note and no diagnosis.
  (`gonk-zxsx`)
- **Four failed jobs with very long names get no diagnosis.** When four jobs
  fail and their names are each near GitLab's 255-character limit, the
  diagnosis prompt does not fit its budget and no session starts.
  (`gonk-37kg.5`)
- **The meter's Role covers every Secret in the namespace.** It creates one
  Secret per project, and a `create` grant cannot be limited by name; the
  `update` and `delete` grants are not limited either. (`gonk-6by9`)
- **A meter pod that starts during a model-gateway outage never becomes
  Ready.** And, as in v0.2.0, an outage of the LiteLLM proxy takes gonk-meter
  and gonk-intake readiness down and fails a `helm upgrade` in flight; no
  alert ships for it. (`gonk-88ez`)
- **The release workflow's pinned downloads have not run yet.** The checksums
  were added in this release and the workflow first runs when this release is
  tagged. (`gonk-5at0`)
- Still true from v0.2.0: NetworkPolicies are enforced only where the
  cluster's network plugin enforces them; the pipeline-fix workflow has been
  exercised against a synthetic project only; and `ledger.postgres.mode`,
  `ledger.postgres.shared.*`, `networkPolicy.ledgerPostgres.namespaceSelector`,
  `ingress.className`, `networkPolicy.ingressController.namespaceSelector` and
  the other selectors under `networkPolicy` still default to the maintainers'
  environment and must be overridden (`gonk-mp43`; the table is in
  `chart/gonk/README.md`, section 2).

No longer in this list since v0.2.0: `gonk-hpgy` (retry feedback for
triage), `gonk-8yux` (a diagnosis carrying a fix kind's keys is now
refused), `gonk-njmr` (the two port-allocating tests).

The identifiers in parentheses are from the maintainers' issue tracker, which
is not public; they are given so a later release can say which one it closed.

## Supply chain

Every image is signed and carries two attestations, verifiable without
trusting this text:

    gh attestation verify oci://ghcr.io/gonk-factory/gonk/gonk-intake:v0.2.1 --owner gonk-factory
    cosign verify ghcr.io/gonk-factory/gonk/gonk-intake:v0.2.1 \
      --certificate-identity-regexp '^https://github.com/gonk-factory/gonk/' \
      --certificate-oidc-issuer https://token.actions.githubusercontent.com

SLSA build provenance and an SPDX SBOM are attached to each image digest. The
images are built by this repository's release workflow from the release commit.
The four images are `gonk-agent`, `gonk-controller`, `gonk-intake` and
`gonk-meter`.
